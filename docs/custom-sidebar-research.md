# Custom sidebar compatibility

Research date: 2026-07-27. Official wiki inspected at commit `389da13ba824d463fcfb98ef5bd1b972dddd3dc6` (2026-07-09).

## Conclusion

The recent sidebar change preserves the documented `CustomSidebarItems` contract for normal sidebar clicks: it wires the outline view action during initialization, waits for `selectedRow`, and sends that item's unchanged `page` value through the common router ([source](../code/apps/Managed%20Software%20Center/Managed%20Software%20Center/Controllers/MainWindowController.swift#L247-L287), [wiring](../code/apps/Managed%20Software%20Center/Managed%20Software%20Center/Controllers/MainWindowController.swift#L803-L812)). **Confidence: high.**

I would not describe support as unconditional yet. Arbitrary HTTP(S) URLs are documented, but a refresh after a Munki run classifies the current page only by its last path component. Thus a remote URL ending in `updates`, `categories`, `myitems`, `detail-*`, and similar internal names can be replaced or refreshed as a Munki page ([source](../code/apps/Managed%20Software%20Center/Managed%20Software%20Center/Controllers/MainWindowController.swift#L653-L693)). Also, the Navigate menu resolves items by title, so duplicate (not prohibited) titles open the first matching item rather than necessarily the chosen one ([source](../code/apps/Managed%20Software%20Center/Managed%20Software%20Center/Controllers/MainWindowController.swift#L264-L273)). **Confidence: high.** Neither issue affects an ordinary direct sidebar click.

## Documented contract and current support

The official [custom-sidebar documentation](https://github.com/munki/munki/wiki/Customizing-Managed-Software-Center-sidebar#customsidebaritems) defines `CustomSidebarItems` as an array of dictionaries with three required string keys: `title`, `icon`, and `page`. `icon` may name one of the four bundled template images or an SF Symbol. The optional `localized_strings` dictionary is keyed by language code; each language dictionary may override `title` and/or `page` ([localized strings](https://github.com/munki/munki/wiki/Customizing-Managed-Software-Center-sidebar#localized-strings)). The implementation reads both documented configuration sources, validates the three required strings, resolves localized overrides, and tries bundled images before SF Symbols ([source](../code/apps/Managed%20Software%20Center/Managed%20Software%20Center/Controllers/MainWindowController.swift#L140-L245), [icon rendering](../code/apps/Managed%20Software%20Center/Managed%20Software%20Center/Controllers/MainWindowController+NSOutlineView.swift#L49-L78)). **Confidence: high.**

Documented `page` forms and routing:

| Form | Official examples/details | Current routing |
| --- | --- | --- |
| `munki://...` | Defaults: `category-all`, `categories`, `myitems`, `updates`. The official [Munki Links](https://github.com/munki/munki/wiki/Munki-Links#details) page also documents `developer-<developer>` and case-sensitive `detail-<pkginfo name>`; URL-encode characters such as spaces. Links are accepted with or without `.html`. | Parsed as a URL and passed to `handleMunkiURL`, which maps the host to an internal page. The page builder supports `detail`, `category`, `categories`, `filter`, `developer`, `myitems`, `updates`, and `updatedetail` page families ([router](../code/apps/Managed%20Software%20Center/Managed%20Software%20Center/Controllers/MainWindowController.swift#L247-L262), [handler](../code/apps/Managed%20Software%20Center/Managed%20Software%20Center/Controllers/MainWindowController.swift#L1263-L1315), [builder](../code/apps/Managed%20Software%20Center/Managed%20Software%20Center/mschtml.swift#L68-L95)). |
| `munki://settings` | Explicitly suggested as a custom sidebar item in [Allowed notification windows](https://github.com/munki/munki/wiki/Allowed-notification-windows#additional-notes). | Opens Settings only when `MSCAllowNotificationWindow` is enabled ([source](../code/apps/Managed%20Software%20Center/Managed%20Software%20Center/Controllers/MainWindowController.swift#L1279-L1285)). |
| Absolute `http://` or `https://` URL | The sidebar documentation permits **any** external HTTP(S) page and shows both top-level and localized examples. | Loaded in the MSC web view; other absolute schemes are not accepted as remote URLs ([source](../code/apps/Managed%20Software%20Center/Managed%20Software%20Center/Controllers/MainWindowController.swift#L247-L262), [HTTP(S) guard](../code/apps/Managed%20Software%20Center/Managed%20Software%20Center/Controllers/MainWindowController.swift#L1220-L1238)). |
| Relative local page name | Not documented by the custom-sidebar wiki. | Accepted as a source-only extension and constrained to `htmlDir` ([source](../code/apps/Managed%20Software%20Center/Managed%20Software%20Center/Controllers/MainWindowController.swift#L258-L260), [path guard](../code/apps/Managed%20Software%20Center/Managed%20Software%20Center/Controllers/MainWindowController.swift#L1185-L1206)). |

The source additionally recognizes `munki://appleupdates` and `munki://notify`, but the custom-sidebar documentation does not promise them as sidebar values; they should not be counted as part of the documented compatibility contract.

## Recommendation and next evidence

Keep the recent selected-row routing change: it is format-agnostic and compatible with documented custom items. Before claiming complete support, add focused coverage for (1) an external page whose final path component collides with an internal route name and then calls `resetAndReload()`, and (2) two custom items with the same title but different pages in the Navigate menu. A manual smoke test should also cover one localized HTTP(S) page and one parameterized `munki://developer-*` or `detail-*` page. The only high-impact unknown is runtime WebKit redirect/canonicalization behavior for external URLs; it may affect sidebar highlighting, but not initial routing.
